# 承認防衛線 v6

公開URL: https://ykyuki1991.github.io/hinata-balance/shonin-defense/

約2分半の縦方向シューティング。操作は相対ドラッグまたはWASD／矢印の移動だけ。自機に近い列の案件を自動照準・自動射撃する。タップによる対象指定は任意で、クリアに必要ない。指は画面下部の余白に置ける。常設の仮想スティック、自由照準、チャージ、攻撃ボタンは廃止。

特殊ボタンは一件の保留／再開のみ。案件ID、処理進捗、期限を保存して退避し、再開時に戻す。保留は8秒の再使用待ち時間があるが、再開はいつでもできる。無敵・弾消し・強攻撃の効果はない。

## 仕事の流れがルール

- 書類を撃つと押印され、経路に沿って次工程へ進む。撃破数と引渡し数は別。
- 未添付の案件は差戻しレールを逆流し、同じ案件IDで添付を備えて再申請される。一周させる時期を、至急案件と比較して選ぶ。
- 並行案件は2枝へ分かれる。片方の承認は保存され、両方がそろった時だけ合流。v5の時間内同時破壊・再起動は廃止。
- 決裁後は3つの送り先へ分配。届いた案件は送り先の待ち列に入り、処理窓が開くと送信される。混雑した待ち列は催促を出す。ボスの完了条件は本体HPではなく必要な引渡し数。
- 淡い封筒の通知は自分の承認案件ではないため、射撃対象にならず流れていく。

第1章は受付、第2章は並行審議、第3章は決裁後連携。第1章の受付分岐は単線／並行を位置で選ぶ。並行を選ぶと受付ボスの後続処理が2枝になり、手間と得点が増える。通常勤務／繁忙日とシードによる到着列の変化、連続処理倍率、持越しの回避でリプレイ性を作る。

## 表現と実装

POWER EGGの公式画面やロゴは使用しない。公開資料から得た受付・逆流・並行合流・決裁後引渡しの構造を架空のレール装置として表現する。実製品に弾幕や締切秒数、射撃による処理は存在しない。汎用ワークフローにも共通する仕組みであり、POWER EGG固有の独占的機構とは主張しない。

Viteのpublic静的ファイル、Canvas 2D、Web Audio。120Hz固定更新、描画DPR上限2、粒子上限140、敵弾上限24。通常URLには診断APIを出さず、?qa=1で読み取りスナップショットを提供する。記録キーはshonin-defense-v6。v5の過去記録を削除しない。本体PWAはゲームをプリキャッシュせず、既存URLで更新できる。

## 検証

単体テストは状態遷移・片指入力・保留の意味・並行合流・受信待ち列・通知の非敵性を検証。ブラウザではゲーム状態を変更せず、移動入力だけで全章・両分岐・ボス・クリアを通す。通常プレイでは特殊操作ゼロ。別の再挑戦で保留／再開を順番に試し、無操作死亡・リトライ・記録保存を検証する。

ChromeはネイティブCDP単一タッチ、WebKitは単一PointerEventとDOM操作。実機iPhoneは未確認。自動操作は内部座標を読めるので、人間の初見難易度や楽しさの証明にはしない。詳細はshonin-v6-design.md、balance、local/public JSON、release記録を参照。
