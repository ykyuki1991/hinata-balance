# RE:WORK 制作・プレイ評価

## 現行版を見て変えたこと

旧版はボス前の敵弾がなく、通常・至急・差戻しの大半を同じ照準操作で処理できた。敵を通すと位置に関係なく直ちにダメージを受け、どの危険を避けたのか分かりにくい。一括否認で敵を倒すと同じ能力を再充填でき、温存より連発が有利だった。固定背景、単一ボス、75秒タイマーによって進行の変化も小さかった。

今回の中心は「難しくする数値」よりも、見るものと判断することを段階的に増やすこと。移動と切り札だけの操作は維持した。

## 場面ごとの判断

| 場面 | 体験の狙いと調整 |
|---|---|
| 開始・序盤 | 2秒の現場表示後に射撃が始まる。初めの2編隊は毎回基本形。操作説明を閉じる手間を設けない。最初から大量の危険を出さず、至急の予告線で「今いる位置を狙われる」を学ぶ。 |
| 第1ボス | 中央だけを狙っても進まず、左右の承認印を壊すと中央が開く。撃破済みの印は✓になり、HPと弱点の色で進展を示す。 |
| 装備選択 | 広く処理する／奥まで通すの2択。被弾で恒久装備を取り上げず、失敗を連鎖させない。次の現場で選択した装備が即座に使える。 |
| 中盤 | 攻撃を出す回覧と、反対側へ戻る再申請で優先順位を変える。背景は実物の受付から、架空の回覧ネットワークへ移る。 |
| 第2ボス | 確認中／受付中の開閉と、列攻撃・狙い弾を組み合わせる。無理に弱点を追わずに待つ時間を作る。 |
| 終盤 | 複数の役割を混ぜるが、発射予告を保つ。背景は夜景と書類棚へ。恒久装備2つを持って最後の現場に挑む。 |
| 月末締め | 集計中／最終決裁の周期、移動するすき間、締切レーザー、扇形の3パターン。機体中心だけを避ければよく、弾が翼に触れただけでは被弾しない。ボス情報とステージ名がスマホで重なったため、配置を修正した。 |
| 切り札 | 画面の弾を消す安全と、全件承認ボーナスの放棄を交換。通常処理とニアミスが再充填につながり、否認による無限の連発を防ぐ。 |
| 終了・再挑戦 | 現場ごとの突破、被弾、全件承認、S〜D評価、実績を残す。同じ編隊でやり直せるので失敗した場所を覚えられる。コンボ実績は編隊数から達成可能な25件に調整し、入力だけで全ルートを突破して実績条件へ到達する回帰テストを加えた。 |

## 検証とその範囲

エンジンの31テストには、通常の移動・一括否認・装備選択だけを使う全ルートの回帰テストを含めた。48本のシミュレーションでは、放置や一定の左右往復だけでは第1ボスを突破できず、敵や弱点の追跡が必要だった。これは自動操作の比較であり、人間の難易度やプレイヤー全体の勝率の推定には使用しない。プレイヤー調査は未実施。

ブラウザでは、ゲーム内部の状態を書き換えずに実入力で操作した。Chromeのタッチドラッグでは、切り札や装備選択の前に指を離し、次の操作から新しいタッチを始める。WebKitはタッチで移動先を指定。PC、iPhone相当、小型スマホ、横向き、画面回転を確認した。初期のタッチ検証ではテストドライバがボタン操作後に既に終了した指IDを再利用していたため、実際の指の操作に合わせて修正した。

描画処理時間は加速時計の値を使わず、実時間プレイでも計測した。公開版ではこのMacのChromeで95パーセンタイル約0.6ms、WebKitで約1ms。これはこの検証環境での値であり、実機iPhoneでの性能値ではない。粒子・発音・敵弾には上限を設けた。

## 公開更新で直した問題

既存PWAの事前キャッシュが、ゲームのディレクトリURLを古いindex.htmlへ結び付けていた。新しいゲームは親PWAの事前キャッシュ対象から除外し、既存のWorkerを更新・有効化する。初回のバージョン付きアクセスではブラウザのHTTPキャッシュも更新した後に元のURLへ戻す。旧版キャッシュを持つ専用ブラウザプロファイルを使い、更新後は元のURLを再度開いても新しい版が維持されることを検証した。プレイ中の強制リロードは行わない。

最終のゲームファイル照合は `shonin-v2-public-integrity.json`、通しプレイは `shonin-v2-public-chromium-desktop.json` と `shonin-v2-public-webkit-iphone.json`、配置は `shonin-v2-public-layouts.json`、更新は `shonin-v2-public-cache-upgrade.json` を参照。v2.0.1以後の修正はキャッシュ更新・バージョン情報・実績閾値で、敵配置・攻撃・当たり判定は変更していない。
