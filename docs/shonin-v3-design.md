# 承認防衛線 v3 — 全方向アリーナへの再設計

## 研究と採用判断

本作の実装に先立ち、以下の開発者解説を確認した。作品の操作・美術・敵を複製せず、判断を生む構造を参考にした。

- **Robotron 2084** — [Eugene Jarvis本人の回顧](https://blog.playstation.com/2017/07/03/my-life-in-games-eugene-jarvis-talks-robotron-smash-tv-and-nex-machina/)。全方向から追われる圧力を、単純な入力で扱う原点。本作では射撃方向の入力を位置取りに置き換え、スマートフォンに二本の照準スティックを要求しない。
- **Nex Machina** — [HousemarqueのHenri Mustonenによる設計解説](https://www.gamedeveloper.com/design/game-design-deep-dive-maintaining-tension-in-i-nex-machina-i-)。読み取れる短い敵群、役割の組合せ、配置で作る移動の目的、緊張と休息の配置を採用。敵を倒すだけでなく印へ向かう計画を作る。
- **Geometry Wars** — [Craig Howardによる敵設計解説](https://blog.playstation.com/?p=152477)、[空間と判断の解説](https://blog.playstation.com/2014/11/13/geometry-wars-3-dimensions-launches-on-ps4-ps3-1125/)。新しい敵を足す理由を、別の行動を要求できるかで判断。機関室の設備は実際に射線・移動を遮り、見た目だけのステージ差にしない。
- **Enter the Gungeon** — [Dave Crooksによる操作ガイド](https://blog.playstation.com/archive/2016/04/05/the-gungeoneers-guide/feed/)。回避に無敵時間と終了後の危険を設け、消耗する弾消しに判断を作る考え方。本作は差戻しボタン一つに移動と局所反撃を統合し、全画面消去を廃止した。
- **DOOM** — [id SoftwareのGDC講演概要](https://www.gdcvault.com/play/1024940/Embracing-Push-Forward-)、[Bethesdaの開発者記事](https://bethesda.net/en-US/news/discovering-the-essence-of-doom)。移動と攻勢を中心に戦闘を組み立てる方向性。本作では近距離承認の得点と印の回収によって踏み込む動機を作る。講演映像を全編視聴したという意味ではない。

## 旧版からの変更

v2は下端で左右移動し、縦の射線・編隊処理・ボスの開閉を見る構造。敵の種類や背景が増えても、プレイヤーの行動は近似していた。新しいv3は同じ題材・タイトル・即座に遊べる入口を保持し、シミュレーション・入力・描画・画面構成を置き換えた。

- 480×600の固定ワールドを全方向に移動。PCと電話で当たり判定・速度・敵配置は共通。
- ドラッグ開始点を中立にする可動スティック。指の位置に機体が飛ばない。PCはWASD/矢印、または同じマウスドラッグ。
- 近くの見通せる敵を自動照準。照準対象の輪を表示。狙いたい回覧元に近づく、設備の横に回る、敵を引き付けて貫通させる操作が攻撃選択になる。
- 「一括否認」を廃止し「差戻し」に整理。移動方向へ短い無敵移動、周囲115の敵へ反撃、140以内の弾のみ否認。遠くの弾と締切線は消えない。自動回復約6.7秒、印回収/かすりで早まる。
- 無傷の全件承認はステージ結果に統合。未処理が下端を通ると失点する旧ルールは廃止。
- 初回は4ライフ。中間クリアで1回復。被弾で武器を失わず、再学習の機会を残す。

## 遭遇の設計

1. **受付ホール**：障害物なし。追尾する未処理 → 至急のロックした突進 → 催促の射線 → 組合せ。敵の出現は1.05秒前から地点と種類を表示。左右だけを見る習慣を解除する。
2. **回覧機関室**：二つの設備が実体を持つ。回覧元は増援を送り、催促は離れて撃つ。設備の陰を利用しつつ回覧元を処理する。再申請は撃破後にもう一度、予告付きで到着する。
3. **月末決裁室**：左右の締切帯が予告後に危険化。保留の環状攻撃、突進、増援との組合せで一方向の周回を崩す。

各現場は4つの遭遇＋ボス。早く処理すると次の遭遇も早まる。単純な時間稼ぎでは得点・印・レベルを稼げない。全体の熟練した検証走行は約90〜110秒、通常の試行は約2〜3分を想定。

敵は一度に最大24体、攻撃予告は最大3件、敵弾は70発。攻撃の予告はロック後に追従しない。催促と至急は移動先を予告するため、同じ方向へ流れ続けず、線を見て切り返す。保留の輪には予告中に緑のすき間方向を表示。

## ボス

- **受付一斉配信**：予告した線へ突進し、停止後だけ承認可能。体当たりを横へかわし、停止地点へ向かう学習。
- **差戻しループ**：二つの中継器を壊すと本体が開く。設備で射線を遮りながら、優先する中継器を選ぶ。
- **月末締め**：縦横の締切線、すき間付き環状弾、狙い弾を交互に使用。半分以降は狙い弾が扇状に広がる。開くタイミングと安全な位置を合わせる。

## 得点・成長・再挑戦

近距離150以内での撃破は基本点×1.5。撃破でコンボ、8件ごとに倍率上昇、最大×5。落ちた決裁印は7秒で消え、拾うと得点と差戻し再充填、9個ごとに最大3段階の射撃速度アップ。回収しない遠距離逃げ撃ちより、近距離と回収を組み合わせたプレイが伸びる。

中間選択は「貫通 / 扇状」「再充填 / 代理防御＋回収範囲」。永続能力強化で難易度を解消する方式は採用しない。自己記録、結果評価、即決/否認などの実績を保存。再挑戦は同じ配置、タイトルに戻って開始すると左右配置が変わり得る。完全なランダム生成ではなく学習を重視。繁忙日は同じ予告時間を保ち、後半の敵群へ挟撃役を追加する。

記録は`shonin-defense-v3`へ保存し、旧版記録は削除しない。ルールが違うため旧スコアとは混算しない。

## 検証の限界

純粋シミュレーションの戦術コントローラは画面に出る位置と予告を正確に読む。勝率は到達可能性・単純行動の抜け道を探す資料であり、人の初見クリア率ではない。

ChromeではCDPによるネイティブのタッチドラッグと二本目の指での差戻しを試験。WebKitではPlaywrightに連続タッチ移動APIがないため、ゲームの実入力リスナーへPointerEventを送り、開始/アクションのタップはネイティブで検証する。実機iPhoneを接続したテストは実施していない。端末上のSafari動作を断言する根拠とはせず、WebKit/iPhone相当の画面・入力経路の検証として記録する。

## 調整履歴とローカル評価

初回シミュレーションでは単純な円運動で通常勤務4/6クリア。予告が現在地点だけを狙うため、同方向に流れ続ければ避けられた。催促と至急に移動先を予告する攻撃を導入し、保留の環状弾のすき間を正面から横へ変更。予告自体は追尾させず、切り返す猶予を残した。最終比較では通常・繁忙日とも静止/左右往復/一定円運動0/6、戦術入力6/6。各種予告を正確に読む検証器の結果であり、人間のプレイ技能を代替する数値ではない。

月末ボスは接近火力で短すぎる問題があったため、HP増量ではなく3段階決裁を導入。各しきい値で一度閉じ、横→縦の締切予告を出し、安全な位置を取り直させる。テストで閉鎖中の弾による段階飛ばしを防止。

画面レビューでは、受付の開いた床、機関室の射線遮蔽物、月末の時計状決裁床と締切線を確認。通知が戦闘空間の敵に重なる問題は下部の装飾帯へ移して修正。小型画面のタイトル/結果を圧縮し、横向きは左右に操作欄を分離してアリーナの縦横比を維持。最終クリア時の「NEXT DEPARTMENT」は「SHIFT COMPLETE」へ修正した。

ネイティブタッチ検証で、結果表示と指を離す瞬間が重なると、結果画面のタイトルボタンへクリックが抜ける問題を検出。新しいオーバーレイ表示時に進行中のジェスチャー由来のクリックを遮断し、新しい押下はすぐ受け付けるよう修正した。テスト時計も明示停止し、入力間は進めず`runFor`でのみ進行する方式に統一。ゲームの勝敗を変更するテスト用書き込みは導入していない。
