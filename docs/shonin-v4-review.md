# v4 プレイレビュー

## 変更の判断

v3の四方から迫るアリーナと回避ダッシュを廃止し、右向きの連射と部位・発生源の処理に集中させた。受付、分岐審議、決裁後の連携を3章の構造にした。常設のステージ列、装備文、操作説明、コンボ解説、ゲーム外のヘッダー・フッターをプレイ中から撤去。説明文の代わりに初出を単独で配置する。

## 実プレイで直した点

- 初期版は序盤ボスが一括承認中に短時間で消えていた。露出した承認口に当たり判定を合わせ、部位処理後の狙い直しが必要になるよう調整した。全周の弾幕は増やしていない。
- 月末は全パーツ破壊後に本体を撃つだけだったため、1パーツにつき本体の3分の1を処理できる構造へ変更。先にすべてのパーツを処理してから攻める選択も残した。
- ゲート停滞の見えない即死タイマーを廃止。ボスの締切は残り10秒を表示。
- タッチで移動中、別の指のボタン押下がclickイベントにならない問題を発見。pointerdownで一括承認を受け付け、キーボードのclick互換も維持した。
- テストの小刻みな押し直しがネイティブタッチのドラッグ判定と競合するため、Chromeでは明確な38pxの8方向ドラッグを使用。WebKitはPointerEvent経由で連続方向を入力。判定値やHPを直接変更していない。
- 縦長の画面で自機が横に歪まないよう世界幅の下限を調整。
- 3ボスの外形を給紙トレー、二連機関、押印装置に描き分けた。

## 評価

序盤は正面の紙列から曲線編隊、添付の弱点、発生源へと増える。中盤は片側を選ぶゲート、逆流、両側完了のゲートを経験し、後半で組み合わせる。終盤は発生源・弱点・並行ポートを同時に処理する。敵弾の消去は通常射撃に組み込み、危険が出る前の処理を有利にした。撃破で火力と一括承認ゲージが育つため、攻撃が次の攻撃につながる。

固定入力シミュレーションは3幅×2難度×3行動×3シードの54本。狙うテストプレイヤーは全18本を約118〜137秒でクリア。棒立ちは全失敗。上下往復だけでは18本中1本のみクリア。これは人間の初見クリア率を示す数字ではない。テストプレイヤーは正確な座標を読めるため、人間より有利。

ローカルではChromeのネイティブタッチ、PCマウス、WebKit縦横で全章・クリア・死亡・リトライ・保存を確認。ブラウザの実時間負荷測定では300フレームのp95がChrome約0.4ms、WebKit約1ms（Mac上の初期場面）。物理iPhoneの性能測定ではない。公開後の最終証拠は `shonin-v4-public-*` に分ける。

## 公開版の最終確認

v4.0.0をGitHub Pagesへ公開。公開URL上でPCキーボード・PCマウス・Chromeタッチ縦持ち・小型スマホ繁忙日・WebKit縦持ち・WebKit横持ちの6本をすべて最初から最後まで確認。全15編隊と3ボス、クリア、自然なゲームオーバー、リトライ、記録保存を通過。フィールドは各環境で画面高の100%。公開ファイル一致、親PWA共存、v3.0.1キャッシュから同じURLでの更新も確認済み。リリース証拠は `shonin-v4-release.json`。物理iPhoneは未使用。
